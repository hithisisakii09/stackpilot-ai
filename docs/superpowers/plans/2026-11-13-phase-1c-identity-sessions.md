Start from `57e9fa4bc0cc092945ffe89248a9af27ea8103c4`. Build the identity service used by the planned local HTTPS routes. Use existing crypto, trust loader, transaction lifecycle and migration-2 tables.

1. Add a restricted control-pool entry point and guarded control transaction wrapper. Keep role selection internal to fixed wrappers. Verify actual database identity, cluster marker, flags, memberships, ownership and effective grants. Test real application/admin pool rejection. Real control-role login provisioning requires owner action. Enable it only within the disposable synthetic test cluster for these tests.
2. Write a failing signed-login behavior test through `createIdentityService({pool,trustPath,origin})`. Load the explicit external trust file at construction and every operation. Derive organization/user/role from pinned trust. Bind signatures to canonical domain, exact HTTPS loopback origin, current identity fingerprint, challenge ID, nonce and expiry. Require canonical Ed25519 signatures and random 256-bit nonce/token values.
3. Store hashed nonces/tokens. Consume challenges atomically with session insertion and audit/outbox. Use the database clock for expiry. Enforce one session per challenge and short absolute TTLs. Add durable issuance bounds plus bounded process-local verification throttling. Expired/replayed/forged challenges and extra caller role/user fields fail closed.
4. Mint opaque handles through authenticated sessions only. Revalidate trust, live session expiry/revocation and identity binding each time a handle is resolved. A fingerprint over key ID, key material fingerprint, org, user and role invalidates role/key changes. Only current owner handles satisfy requireOwner. Support idempotent logout/revocation and session-bound CSRF verification for future routes. Return generic errors and avoid credential logging.
5. Add a separate synthetic identity database to the existing harness. Test successful signing/session use, replay and races, wrong nonce/signature, origin binding, absent profile, cross-tenant/caller role forgery, expiry, logout, trust removal/rotation/downgrade, opaque-handle forgery, admin/app pool denial and privilege drift. Keep private fixture keys in memory and public trust fixtures outside the repository.
6. Review, fix reproduced findings, run full existing npm test/build/preflight and exact-SHA Linux/Chromium/axe CI. Deliver a checkpoint with exact versions, tests, warnings, limitations and next steps. Hosted/local HTTP routes and independent approval services follow this identity-service slice.
