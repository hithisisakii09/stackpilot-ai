## What the buyer must compare
The useful question is not "which SEO tool wins?" but whether a chosen plan can audit an owned website at the required scale, depth and frequency, within an understood budget. Crawl credits, page caps and export rows are *different metrics*. Do not equate them or use unsupported quality scores.

### 1. Define the site's audit profile
- Authorized website/property and ownership-verified access; no third-party crawling without permission.
- Number of canonical URLs, subdomains, subfolders and dynamic/query-parameter paths.
- Need for JavaScript rendering, user agents, mobile/desktop, scheduling and sitemap/list-of-URLs crawling.
- Desired re-crawl frequency; link changes and CI acceptance criteria.
- Reporting recipients, export rows and API/report access rights.
- Privacy, robots/crawler-load controls, crawl rate, sensitive paths, credentials never shared with StackPilot.

### 3. A fair future test protocol (NOT EXECUTED)
Only where two lawful, already-authorized trial or subscription environments exist and do not violate the ₹0 budget:
1. Use the same owned/public-consented site and freeze a test set of URLs.
2. Document robots permissions and crawler load controls; do not submit private data.
3. Fix scope: exact host, URL discovery, sitemap, JS setting, user agent, crawl timing and depth.
4. Record starting and ending credit/page allowance separately and any skipped URLs.
5. Classify observed issues by type with verifiable example URLs, false positives and missed pages, not raw issue-count 'wins'.
6. Re-run and inspect report/export constraints. Report both providers' limitations and sampling bias.

If no permitted accounts exist, record **Not tested**. Vendor documentation is not a substitute for benchmark evidence.
